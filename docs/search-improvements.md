# 검색 행동·입력 안내·평가 fixture 개선

## 2026-09-17 — 시범 보고서 후속 제품 개선

[Terra 90회 시범](terra-subscription-pilot-90-2026-09-17.md)의 관측을 바탕으로 검색 안내·케이스를 `2.1.0`, 채점기를 `3.1.0`으로 갱신했다. fixture 응답은 `2.0.0`을 유지한다. 아래 변경은 제품과 평가 경로의 구현이며, 새 모델 실행으로 성능 개선을 확인했다는 뜻은 아니다.

- URL이 없는 자료에는 제목을 일반 텍스트로 표시하고 “출처 URL 미제공”을 알리도록 공통 지침·도구 설명·출력 스키마에 명시했다. 실제 반환 자료에 `url=null`이 있을 때만 응답 텍스트와 warnings에 해당 안내를 붙인다. 메인 페이지를 해당 자료의 출처로 대신 연결하지 않는다.
- 일반적인 자료·수업자료 요청은 전체 검색하도록 안내했다. 평가자료·수업안처럼 유형이 명확하면 대응 코드를 쓰고, 학습 주제의 사진·영상(`edntpd`)과 글꼴·이미지·음악·PPT 등의 제작 소재(`asset`)를 상위 필드·도구 설명에서 구분한다.
- 검색어 제안만 요청하거나 추가 검색을 금지하면 0건 응답의 자동 재검색보다 종료가 우선하도록 지침·입력 설명·응답 안내를 일치시켰다. `ambiguous-4`의 요청과 rubric에도 추가 검색 금지를 명시했다.
- `INVALID_INPUT`만 안내대로 수정해 다시 호출할 수 있다. 다른 제품 오류는 동일·변경 입력 모두 이번 요청의 자동 재호출을 종료하도록 메시지를 통일했다. 기존 HTTP 내부 재시도 정책은 유지하며 서버에 사용자 대화를 차단하는 상태를 추가하지 않았다.
- 엄격한 입력 스키마를 유지하면서 허용 6개 필드와 완전한 입력 예시를 제공한다. `max_results`는 제거하고 `pageSize`로 바꾸도록 안내하며 잘못된 enum이나 별칭을 자동 허용하지 않는다.
- 서버 핸들러 오류의 안전한 코드를 `_meta["edunet/errorCode"]`에 추가했다. CLI에서 `isError`가 생략돼도 채점기는 알려진 구조화된 오류 코드를 읽어 `retry_after_terminal_error`를 감지한다. 명시적 정상 플래그·정상 결과 구조와 충돌하는 메타데이터나 검색 발췌의 오류 단어는 그 근거로 쓰지 않는다. 원시 trace는 수정하지 않는다.

모델에 전달되는 MCP `tools/list`와 응답은 로컬 연결에서 검사한다. 최종 답변 작성과 검색 호출 선택은 클라이언트 모델이 수행하므로, 이 구현만으로 지침 준수나 릴리스 통과를 주장하지 않는다. `falseOriginalRead`의 의미 판단은 계속 사람 검토 대상이다.

30개 시나리오 ID·그룹 분포·허용 호출 수와 모의 응답은 유지했다. 케이스 문구와 채점기가 바뀌었으므로 기존 90회 결과와 직접 비교한 개선률은 산출하지 않는다. 과거 관측 JSON·집계·검토 자료는 보존하며, 보고서 생성기는 현재 케이스 버전·해시가 원본과 다르면 출력 전에 거절한다. 과거 보고서를 재생성할 때는 해당 소스 스냅샷을 사용한다.

변경 전 코드·문서는 [스냅샷](../.scratch/2026-09-17-product-improvements-tncsBf/before/snapshot.json)에 보존했다. 타입 검사와 빌드를 통과했고, [전체 계약·회귀 검사](../.scratch/2026-09-17-product-improvements-tncsBf/contract-final.json)는 **101/101 통과**, [고정 응답 smoke](../.scratch/2026-09-17-product-improvements-tncsBf/smoke.json)는 **30/30 자동 검사 통과**였다. 최초 계약 검사의 1건 실패는 종료 안내가 추가되기 전 오류 문구 전체를 기대하던 테스트였으며, 오류 코드·안전한 메시지·원시 오류 비노출을 확인하도록 수정한 뒤 전체 검사를 다시 통과했다. 최초 실패 기록도 같은 폴더의 `contract.json`에 남겼다.

[최종 검증](../.scratch/2026-09-17-product-improvements-tncsBf/validation.json)에서 원본 결과 파일 7개의 바이트 해시 보존, 30개 ID·그룹·허용 조건·모의 응답 불변, 새 버전 기록, 사람 검토 양식 공란을 확인했다. 실제 모델과 EDUNET 실검색은 실행하지 않았다. 변경된 `dist`까지 빌드했으므로 새 MCP 서버 프로세스에서 개선 사항을 사용한다. 이미 실행 중인 서버에는 재시작이 필요하다.

## 2026-09-16 — 이전 구현 기록

후속 작업: 결과 보존·판정 분리·재현 가능한 재평가 체계는 [평가 실행 안내의 v3 절](../evals/README.md#결과-보존판정-분리재평가-v3)에 구현했다. 채점기 3.0.0은 환경 오류와 모델 버전·사람 검토 보류를 제품 실패에서 분리하며, 릴리스 분모 90과 환경 오류·보류 veto를 유지한다. 이전 제품 전체 스냅샷이 없어 현재 제품을 새 기준선으로 보존했다. 최종 계약 검사 85/85 통과. Terra 연결 점검은 429 `credit_balance_exhausted`로 차단되어 실제 성능 평가는 진행하지 못했다. 아래 v2 기록은 당시 결과로 보존한다.

2026-09-16. 이번 변경은 검색 규칙, 잘못된 입력의 수정 안내, 모의 응답과 채점 개선에 한정한다. 별도로 진행된 평가 환경 분리 설정은 유지한다. 실제 모델 90회나 실검색 평가는 이 변경 확인 과정에서 실행하지 않는다.

## 검색 도구

`src/search-guidance.ts`에서 모델 안내 버전 `2.0.0`을 관리한다. 서버 공통 지침과 도구 설명에 검색 중단 규칙을 제공하고, 각 응답에는 관측된 상태에 맞는 안내를 붙인다.

- 요청에 답할 관련 자료를 확보하면 종료한다. 같은 조건을 반복하지 않고 사용자 요청 없이 모든 페이지를 순회하지 않는다.
- `hasNextPage=false`이면 같은 조건의 이후 페이지를 호출하지 않는다. `null`이면 미확인으로 설명하고 자동 페이지 이동을 중단한다.
- 페이지 이동 시 검색어·카테고리·정렬·검색 범위·페이지 크기를 유지한다. 조건을 바꾸면 1페이지부터 시작한다.
- 전체 건수 0일 때 핵심 주제를 유지하면서 학년·과목 등 부가 표현을 줄이거나 동의어를 사용한다. 자동 검색어 수정은 최대 2회다. 사용자가 재검색을 원하지 않으면 종료한다.
- 명시한 카테고리·정렬·제목 검색 조건을 임의로 풀지 않는다. 검색 범위를 넓혔다는 사실과 학년·과목 적합성의 미확인을 밝힌다.
- 인증·설정 오류에는 설정 점검을 안내한다. 서비스 오류가 반환되면 이번 요청에서 자동 재호출하지 않는다. HTTP 계층의 기존 시간 제한·재시도 정책은 유지한다.

이 규칙은 모델 안내와 평가 기준이다. 검색 서버에 대화 이력을 저장해 후속 호출을 강제로 차단하는 기능을 추가한 것은 아니다. 실제 모델의 준수율은 별도 재평가가 필요하다.

## 입력 오류

기존 JSON Schema의 엄격한 타입·enum·범위를 유지하고 Zod 오류 메시지를 필드별로 제공한다. SDK가 핸들러 실행 전에 입력을 거절하는 경우에도 MCP 응답에 수정 안내가 전달된다.

| 잘못된 입력 | 수정 안내 |
|---|---|
| `pageSize: 100` | `pageSize: 20`, 추가 페이지 존재 여부 확인 |
| `categories: ["평가자료"]` | `categories: ["evl_data"]` |
| `categories: "evl_data"` | 문자열이 아닌 코드 배열 사용 |
| `page: 51` | 최대 50, 조건을 좁혀 `page: 1` |
| 잘못된 sort/searchType | 허용 값 안내 |
| 빈 검색어·알 수 없는 필드 | 검색어 길이 및 허용 필드 안내 |

잘못된 값을 조용히 보정하거나 입력 검사를 느슨하게 하지 않는다. 오류 메시지는 통제된 문구이며 전달받은 값이나 알 수 없는 필드명을 되풀이하지 않는다.

## 평가 v2

기존 30개 시나리오와 그룹 분포를 유지하면서 케이스·fixture·채점기를 `2.0.0`으로 갱신한다. 모의 응답은 호출 순서가 아니라 검색 개념·카테고리·페이지·정렬·제목 검색 조건에 따라 선택된다. 두 실행 경로(메모리 MCP와 stdio MCP)가 같은 모의 백엔드를 사용한다.

정의되지 않은 요청은 `FIXTURE_MISMATCH`로 기록하며 마지막 응답을 반복 반환하지 않는다. 이는 `harnessErrors`로 분리하고 릴리스 통과를 차단한다. 그 요청 자체의 명백한 입력·카테고리·검색 개념 위반은 별도 행동 실패로 남을 수 있다.

핵심 주제는 모든 검색에서 유지해야 한다. 초기 학년·과목 표현이 요구된 시나리오는 관측된 0건 이후에만 해당 표현을 완화할 수 있다. 학년 적합성에 대한 과장은 최종 답변의 사람 검토로 판단한다. 같은 검색 반복, 마지막 페이지 이후 호출, 다음 페이지 증거 없는 이동, 조건 변경 후 페이지 미초기화, 서비스 오류 뒤 재검색을 따로 판정한다.

실행 보고서에는 case/fixture/scorer/searchGuidance 버전과 관련 구현 해시를 남긴다. 기존 결과를 새 fixture로 실행한 것처럼 바꾸지 않는다. 과거 결과의 재채점은 별도 파일에 이전 자동 판정을 보존한 회고 분석으로 남긴다.

최종 릴리스 기준은 90회 중 81회 이상 성공, 중대 위반 0건, 전체 사람 검토 완료로 유지한다. 로컬 회귀 검사나 고정 응답 smoke 통과는 실제 모델 성능 개선의 증거가 아니다.

## 로컬 확인 방법

과거 `evals/results/`를 덮어쓰지 않도록 별도 경로를 지정한다.

```sh
npm run typecheck
npm run build
node evals/contract.mjs --out .scratch/search-v2-contract.json
node evals/ai.mjs --adapter evals/adapters/smoke.mjs --model smoke --model-version smoke --repetitions 1 --out .scratch/search-v2-smoke.json --review .scratch/search-v2-smoke-review.json
```

계약 검사는 기존 테스트와 새 회귀 검사를 함께 실행한다. 고정 응답 smoke는 30개 케이스의 실행기·MCP·fixture·채점 연결과 보고서 버전 기록을 확인한다. 사람 검토 양식은 비워 두며, smoke 결과의 `kind`는 `smoke_only`로 기록한다.

2026-09-16 확인 결과: TypeScript 타입 검사·빌드 통과, 전체 계약 검사 **80/80 통과**, 고정 응답 smoke **30/30 자동 검사 통과**. 결과는 위 `.scratch/` 경로에 기록했으며 기존 `evals/results/` 산출물은 변경하지 않았다. 실제 모델을 사용한 90회 재평가와 최종 사람 검토는 미실행이다.
