## 수정한 문제

공식 성취수준 게시판의 목록·상세·첨부를 연결했고, 게시판/게시물/첨부 소속을 검증합니다. 학교급·교과 조건을 발견에 반영하고 공식 다운로드 경로를 필요한 범위로 지원합니다. 10MiB를 넘는 첨부는 읽기 전에 제한 사유를 안내합니다.

실제 과학 PDF에서 관측한 표의 병합 셀과 교과 문맥 오류를 수정했습니다. 명시적 표 선으로 검증되지 않는 관계는 추론하지 않습니다. 이 보수적 동작 때문에 일부 표는 구조 미확인 경고를 유지합니다.

RC1의 배포 동일성 실패는 Vercel이 빌드 중 `vercel.json`에 `name: edunet-mcp`와 `version: 2`를 추가하고 한 줄 JSON으로 다시 저장해서 발생했습니다. 업로드된 원본은 로컬 파일과 같았고, 원격 manifest의 해당 파일 해시는 추가된 두 값과 재직렬화로 정확히 재현됩니다. 별도 진단 배포의 빌드 로그로 실제 추가 값을 확인했습니다.

RC2는 두 값을 명시하고 `vercel.json`의 모든 설정을 재귀 키 정렬 JSON으로 해시합니다. 배열 순서는 유지하고 설정을 제외하지 않습니다. 다른 파일은 원본 바이트를 해시합니다. 설정 내용이나 제품 파일 변경은 여전히 불일치로 검출하며 이 동작은 회귀 테스트로 검증했습니다. manifest의 `fileHashEncodings`에 규칙을 기록합니다.

로컬과 원격의 전체 `files`, `sourceDigest`, `sourceCommit`이 일치했습니다. 로컬의 제품 경로는 clean이며 원격은 `.git` 부재로 `gitClean:null`입니다. null을 clean으로 해석하지 않습니다. 이 메타데이터 차이로 전체 manifest digest는 로컬과 다르므로, 로컬 소스 비교 증거와 원격 manifest 원본을 각각 고정했습니다. 평가 중에는 고정 원격 manifest 전체와 각 MCP 응답 헤더가 일치해야 합니다.

## 독립 RC 평가

제품 구현과 분리한 작업 `성취수준 RC 독립 평가자 구현 및 평가`에서 공식 원문 30종과 90개 시나리오를 준비했습니다. 원문 정답은 제품 parser와 별도 도구로 작성했습니다. 고정 corpus SHA256은 `4602a056b74e8b4c1581efb4b2859e8be0c5180d53a06356f84d4eef4a3600aa`입니다.

평가 작업의 `work/rc2-handoff/rc-lock.json`에 RC2 원격 manifest, 배포 식별, 로컬 소스 대조 증거, 검사 결과 및 10MiB 제한을 고정하여 전달했습니다. 이전 3개 진단이나 개발 smoke는 90개 평가 건수에 합산하지 않습니다.

첫 `rc2-20260920` 실행은 18건 처리 후 중학교 수학의 `metadata_only` 원문 fallback을 20페이지 이상 읽으며 지연되었습니다. 페이지마다 약 14초가 걸리고 구조화 레코드가 없었습니다. 독립 평가자는 첫 실행을 interrupted/partial로 보존하고 수집 프로토콜을 변경했습니다. 최대 페이지 크기를 고정하고 `metadata_only`·레코드 0개·`NO_MATCHING_RECORDS`가 함께 확인될 때만 구조화 실패로 기록하여 남은 원문 읽기를 중단합니다. 해당 사례는 부분 수집으로 남고, `verified_extraction`은 끝까지 cursor를 따라갑니다. 자체 검사 46/46을 통과한 뒤 `rc2-20260920-v2`에서 90개를 처음부터 실행하며, 첫 실행과 합산하지 않습니다. 제품 후보와 정답 corpus는 변경하지 않았습니다.

v2는 27건 처리 후 사회 문서에서 다른 경고로 같은 지연이 나타나 중단 기록으로 보존했습니다. 최종 v3는 경고 코드나 문서명을 기준으로 삼지 않습니다. `metadata_only`·빈 `records`·유효한 다음 cursor이면 남은 raw 수집을 중단하고 `fullRawCollection:false`인 부분 수집으로 명시합니다. 읽지 않은 페이지에도 레코드가 없다고 단정하지 않습니다. 잘못된/반복 cursor는 오류로 기록하고 `verified_extraction`은 계속 끝까지 읽습니다. 평가기 자체 검사 49/49을 통과한 후 `rc2-20260920-v3`에서 전체 90건을 처음부터 실행합니다. 정확도 점수 개선을 위한 문서 선택·정답 수정·실패 결과 덮어쓰기는 하지 않았으며, 두 프로토콜 조정과 구현자 요청 이력은 평가 독립성의 한계와 함께 보존합니다.

### 최종 관측 결과

**후속 감사 정정:** RC3 종료 후 독립 감사에서 v3 발견 수집기가 첫 검색 응답만 읽은 결함을 확인했습니다. 아래 RC2 발견 51/90은 첫 응답 범위의 관측입니다. 나머지 39건 중 10건은 `hasNext:true`였으므로 후속 페이지 미수집이며 확정 미발견으로 해석하지 않습니다. 당시 점수는 보존하고 새 v4 실행과 합산하지 않습니다. [RC3 수집기 감사](achievement-rc3-validation-2026-09-20.md)를 참조합니다.

최종 v3 실행은 `08:02:52Z`부터 `08:17:33Z`까지 90개 시나리오를 처리했습니다. 경로 수집 종료 85건·원문 부분 수집 5건·예외 0건입니다. 발견 51/90, 첨부 51/90, 다운로드 44/90, 파싱 및 구조화 반환 39/90이며 상위 단계 미도달은 미측정으로 남깁니다. 반환 레코드의 관측 정밀도는 157/190(82.63%), 수집된 근거 인용의 원문 존재는 2,248/2,248입니다. 부분 수집 때문에 두 수치를 전체 Gate 통과로 바꾸지 않습니다. 배포 manifest 전후와 201개 RPC 응답의 digest가 일치했습니다.

불일치 33개는 수준 라벨·설명이 없는 추가 레코드이며, 그중 3개는 기준 문장도 중간에서 잘렸습니다. 자동 critical 플래그 69회에는 같은 레코드의 중복 집계와 실제 원문에 있는 영역 번호를 허용값이 놓친 사례가 포함됩니다. 이를 조작 코드나 확정 치명 오류 69건으로 해석하지 않습니다. 실제 원문을 갖춘 사람 판정이 필요합니다.

고등학교 정보 HWP의 `WORKER_OUTPUT_TOO_LARGE` 3회 뒤 다른 문서에서 `WORKER_CIRCUIT_OPEN` 4회가 관측됐고, 뒤의 별도 시나리오에서 다시 읽기에 성공했습니다. 통제 장애 주입은 아닙니다. 10MiB 초과 12시나리오는 모두 발견 실패로 끝나 크기 초과의 명시적 처리까지 평가하지 못했습니다.

최종 원본은 독립 평가 작업의 `outputs/runs/rc2-20260920-v3/final-report.md`, `score.json`, `analysis.json`, `rpc.jsonl`, `final-artifact-hashes.json`입니다. RC2는 출시 승인 요건 미충족이며, 발견·표 병합·코드 형식·기준만 있는 추가 레코드·Worker 출력 범위를 RC3에서 보완하여 같은 관측 corpus로 회귀 평가합니다.

사람의 표 관계 최종 검토, 실제 모델 최종 답변 실험, 운영과 유사한 격리 환경의 장애 주입 및 원계획의 누락된 최종 Gate는 별도 미완료 항목입니다. 이 항목을 수행하거나 사람이 판정한 것처럼 기록하지 않습니다. 독립 평가 수치가 확인되기 전 출시 승인을 내리지 않습니다.

## 공개 전환 및 되돌리기

현재는 검증 배포이며 공개 서비스 승격을 하지 않았습니다. 검증 배포에서 실패가 확인되면 기존 공개 서비스에 변경이 없으므로 운영 rollback이 필요하지 않습니다. 향후 모든 출시 기준과 사람 판정을 확보한 뒤 고정 검증 배포를 승격해야 하며, 새로 빌드하여 평가되지 않은 산출물을 공개하지 않습니다. 문제가 생기면 보존한 기존 배포 ID로 도메인을 되돌리고 원인을 기록합니다.
