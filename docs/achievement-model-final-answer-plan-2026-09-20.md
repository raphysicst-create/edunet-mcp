# 성취수준 모델 최종 답변 평가 계획 — Luna·Haiku 각각 90회

작성일: 2026-09-20. 사용자 최종 확정 범위: 성취수준 평가, Luna High와 Haiku 기본 effort, 각각 90회. Haiku는 effort 값을 명시하지 않고 모델의 기본 동작을 사용한다. 이 문서는 실행 계획이며 실제 모델 호출은 수행하지 않았다.

## 1. 평가 단위와 모델 설정

공식 원문 30종 × 문서별 discovery/code/natural 3개 시나리오 = 모델별 90개 독립 세션, 총 180개 평가 슬롯이다. 같은 질문을 3회 반복하는 기존 일반 검색 평가와 구분한다. 한 세션의 여러 모델 응답·MCP 호출은 최종 답변 1건을 만들기 위한 과정이며 별도 건수로 세지 않는다.

| 평가군 | 요청 모델·설정 | 본 평가 | 현재 실행 조건 |
|---|---|---:|---|
| Luna | `gpt-5.6-luna`, reasoning effort `high` | 90회 | 실제 계정 접근·관측 모델·설정 전달 확인 필요 |
| Haiku | Haiku, 기본 동작 사용·effort 인자 생략 | 90회 | 실제 계정 접근·관측 모델·effort override 부재 확인 필요 |

[OpenAI 공식 Luna 문서](https://developers.openai.com/api/docs/models/gpt-5.6-luna)는 high 지원을 명시한다. [Anthropic 공식 모델 표](https://platform.claude.com/docs/en/models/overview)는 Haiku 4.5(`claude-haiku-4-5-20251001`)를 extended thinking 지원, effort 미지원으로 표기한다. 문서 확인일은 2026-09-20이다.

사용자의 최종 선택에 따라 Haiku는 CLI의 `--effort` 및 API의 effort 필드를 생략한다. 사용자 설정·환경변수에서 effort override가 상속되지 않도록 확인하며, extended thinking이나 thinking budget도 별도로 강제하지 않는다. 실행 준비에서 정확한 Haiku 모델 ID·CLI 버전·기본 thinking 동작을 확인해 기록하고 본 평가 동안 유지한다. 요청 effort는 `default`로 표시하되 관측 effort가 없으면 null로 기록한다. 기본 동작을 high 또는 medium으로 임의 환산하지 않는다. Haiku High 미지원에 따른 기존 보류 조건은 해소되었으며 Sonnet은 평가 대상에 포함하지 않는다.

## 3. 질문과 정답·채점 규칙 준비

1. 90개 scenario ID와 `question`을 그대로 가져와 모델 입력 manifest를 만든다. 질문·시나리오 순서·공통 지침·도구 스키마의 해시를 고정한다.
2. 모델에는 사용자 질문과 실제 서버 지침·도구 스키마만 제공한다. 기존 `searchArguments`, `readFilters`, 기대 URL, 정답, rubric, 과거 점수는 전달하지 않는다. 검색어·필터·문서·첨부 선택은 모델이 수행한다.
3. discovery 30건은 적합한 공식 자료 발견·설명을 평가한다. 사용자 요청에 없는 특정 코드 추출을 의무화하지 않는다. code 30건은 해당 코드의 수준·설명·출처를, natural 30건은 주제와 실제 성취기준의 연결 및 답변을 평가한다. 관련된 다른 공식 자료도 정당한 답일 수 있는 질문은 원문 대조로 판정하고 미리 정한 한 URL과 다르다는 이유만으로 오답 처리하지 않는다.
4. RC4의 결합 학년 표기 허용값 누락은 새 최종 답변 rubric에서 원문과 대조해 실행 전에 정리한다. 원래 corpus·RC4 점수는 보존하고 새 rubric 버전·변경 사유·근거를 별도 저장한다. 사람이 확인하지 않은 판정은 미검토 상태로 남긴다.
5. 기존 10MiB 초과 문서 4종·12개 시나리오를 유지한다. 읽기가 필요한 요청에서는 한계 설명·공식 출처·가능한 다음 행동을 평가한다. 발견만 요구한 질문에서는 관련 자료 제시를 평가한다. 읽지 못한 내용을 지어내면 실패다.

## 4. 실행기 준비

현재 `evals/subscription-pilot.mjs`는 Terra/medium 및 일반 검색 fixture를 고정하고, `evals/claude-pilot.mjs`는 Sonnet/medium 및 검색 도구 하나를 전제로 한다. 기존 `full` 명령을 그대로 실행하면 이번 평가가 되지 않는다. 새 실행기는 Luna의 high를 명시하고, Claude 측 Sonnet 제한과 medium 강제를 제거해 Haiku 및 effort 인자 생략을 지원해야 한다.

새 성취수준 최종 답변 실행기에 공통 90개 시나리오 로더, 원격 MCP 감사 프록시, 모델별 어댑터, 중단·재개 기록, 최종 답변 수집 및 검토 패킷을 구현한다. 제안 경로는 `evals/achievement-model/`이며 아직 구현된 명령으로 제시하지 않는다.

- 기존 구독 CLI 경로를 우선 검토하되 계정 접근과 설정 적용을 사전 확인한다. API 경로로 바뀌면 별도 실행 조건으로 고정한다.
- 두 모델에 동일한 사용자 질문·공통 지침·MCP 기능을 제공하고 매 시나리오 새 세션을 사용한다. 다른 세션의 답변을 넘기지 않는다.
- 정답·평가기 파일을 모델 작업공간 밖에 두고 파일 접근·셸·브라우저·다른 MCP·개인 지침 상속을 실제로 제한한다. 격리를 증명하지 못하면 관측 실험으로 표시하고 통제된 비교·출시 근거로 승격하지 않는다.
- 프록시는 모델이 요청한 호출만 실행한다. 후속 검색 페이지·본문 cursor를 자동 수집해 모델의 누락을 보완하지 않는다. 최종 답변에 필요한 범위와 남은 범위 안내를 채점한다.
- 참조·cursor는 서버 응답으로 발급된 것만 사용한다. 토큰과 배포 보호 인증값은 결과물에 기록하지 않는다.
- 모델 요청 ID, 관측 ID, 요청 effort, 설정 전달 증거, CLI/어댑터 버전과 해시를 별도 필드로 저장한다. 관측 불가 값은 null로 남긴다.

실행기 검사는 세션 독립성, 90개 ID 중복·누락, 모델·설정 불일치, 허용 외 도구, MCP 감사 누락, 최종 응답 누락, 페이지·cursor 처리 기록, 중단·재개 및 비밀값 마스킹을 검증한다. 문서만 작성한 현재 단계에서 이 검사를 통과했다고 기록하지 않는다.

## 5. 실행 순서와 건수

| 단계 | 모델별 건수 | 완료 조건 |
|---|---:|---|
| 설정·연결 확인 | 1회 | 정확한 모델·설정, 원격 MCP, 도구 목록·감사 기록 확인 |
| 대표 점검 | 6회 | PDF/HWP, 자연어·코드, 후속 검색, 파일 제한 등을 포함한 고정 사례에서 실행기 검증 |
| 본 평가 | 30회 × 3개 배치 = 90회 | 고정된 90개 ID를 각 1회 실행 |
| 검토·집계 | 답변 90건 | 자동 관측과 사람 검토를 분리해 기록 |

설정·대표 점검 7회는 본 평가 90회에서 제외한다. 두 평가군이 모두 실행 가능하면 예정 모델 세션은 194개(본 평가 180 + 점검 14)이며, 도구 루프에 따른 provider 호출 수는 더 많다. 점검 추가·재실행이 필요하면 별도 건수로 공개한다.

대표 사례는 결과를 보기 전에 선정한다. 점검 중 모델의 실제 오답을 실행기 오류와 구분하며, 단순 오답은 전체 평가를 막거나 쉬운 사례로 바꾸는 근거가 아니다. 실행기·질문·설정을 수정하면 새 해시로 다시 고정한다.

전체 90개는 문서 10종씩 3개 배치로 나누고 학교급·교과·형식·제한 문서를 분산한다. 두 모델은 같은 시나리오 순서를 사용하며 실제 시작 시각을 기록한다. 사전 점검은 모델별 1개, 전체 최대 2개로 진행한다. 2026-09-20 실행 중 대표 사례의 처리 시간 차이를 확인해 본 평가는 모델별 최대 3개, 전체 최대 6개 독립 세션으로 조정하기로 했다. 이 변경은 사전 점검 이후 `full-stage-lock.json`에 고정하며 질문·effort·모델·세션 한도는 유지한다. 두 모델의 진행 속도와 실행 시점·공유 서버 부하가 다를 수 있어 지연시간을 순수한 모델 성능 차이로 해석하지 않는다.

시나리오 제한 시간·총 도구 호출·출력 상한은 대표 점검에서 정상 경로에 충분한지 확인한 뒤 두 평가군에 공통으로 고정한다. 시작 제안은 세션당 10분·도구 60회이며 본 평가 중 임의로 늘리지 않는다. 한도 소진은 답변 실패 또는 실행 미완료로 보존한다. 지원되는 모델별 출력 한도와 thinking 설정 차이도 기록한다.

## 6. 실패·중단·재개

평가 분모는 모델별 90개 슬롯이다. 모델의 부정확한 답변도 완료된 최종 답변으로 기록하되 성공으로 세지 않는다. 인증 실패·quota·모델 바뀜·설정 미지원·배포 변경·감사 누락은 해당 평가군을 중단한다. EDUNET의 정상적인 제한·오류 응답과 provider 장애를 구분한다.

최종 답변 없는 슬롯을 지우고 성공 사례로 대체하지 않는다. 실행 장애 재시도는 동일 scenario ID의 별도 attempt로 보존하고 최초 실행 기준 지표와 복구 후 완결성을 나누어 보고한다. 성공·실패 답변을 얻은 슬롯은 점수 개선을 위해 재실행하지 않는다. 같은 조건이 유지될 때만 미완료 슬롯을 재개하고, 제품·질문·모델·설정 변경은 새 평가 cohort로 분리한다. 90건을 채우지 못하면 부분 실행으로 명시한다.

## 7. 답변 검토와 결과 판정

답변별로 요청 충족, 코드·원문 수준 라벨·설명 정확성, 학교급·학년군 보존, 공식 출처·위치 일치, 읽은 범위와 실패 안내의 정직성을 평가한다. 근거 없는 학년 단정, 수준·설명 창작, 잘못된 출처, 원문 열람 허위 주장, 비밀값 노출은 별도 중대 위반 항목으로 남긴다.

원문·표 관계 30종과 최종 답변 180건의 사람 검토 패킷을 작성한다. 모델명을 가린 검토 자료에 실제 질문·답변·도구 증거·원문 위치를 제공한다. 자동/LLM 보조 판정과 사람 판정을 분리하고, 사람의 reviewer·reviewedAt·판정을 자동으로 채우지 않는다. 미검토는 pending이다.

새 run 폴더 `evals/results/achievement-model/<run-id>/`에 공통 `evaluation-lock.json`, `prompts.jsonl`, `rubric.json`, 모델별 `preflight.json`, `runs.jsonl`, `attempts/`, `review.json`, `report.md`, 그리고 공통 `comparison.md`, `artifact-hashes.json`을 보존한다. 원본 결과를 덮어쓰지 않는다.

진행 순서는 **질문·rubric·RC 고정 → 실행기 구현·검사 → 모델·설정 확인 및 1+6회 점검 → 모델별 90회 → 사람 검토 → 비교 보고**다. 확정된 두 평가군은 Luna High와 Haiku 기본 동작이며, 같은 effort 조건을 맞춘 비교로 해석하지 않는다.

시간·비용은 대표 점검의 실제 사용량으로 추산한다. 본 실행 시간은 동시성 1 기준 각 모델의 평균 세션 시간 × 90, 비용은 평균 세션 비용 × 90에 점검분을 더한다. 예를 들어 평균 2분이면 모델별 약 3시간이며 실제 예측값은 아니다. 구현·사람 검토 시간은 별도로 잡는다. 현재 계정 잔여량·실제 처리 시간·비용은 확인하지 않았고 모델 호출은 0회다.
